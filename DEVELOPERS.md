# Developer guide

How Local Code RAG is built, tested and released, and how indexing and search work inside. For using the app, see [README.md](README.md).

## Layout

```
crates/rag-core        indexing, chunking, embeddings, LanceDB storage, config, locks, export/import
crates/rag-mcp         headless MCP server (stdio, rmcp) used by Claude Code
crates/workspace-hack  generated by cargo-hakari (shared dependency features)
src-tauri/             Tauri v2 desktop app (commands in src/lib.rs, build.rs stages the sidecar)
ui/                    React + TypeScript + Tailwind v4 frontend
scripts/               fetch-winml.mjs (Windows ML runtime), prepare-sidecar.mjs (builds rag-mcp for bundling)
third_party/hf-hub     hf-hub 0.5 with a one-line TLS patch (see PATCHED.md)
.github/workflows      ci.yml (develop, PRs), release.yml (main)
```

## Requirements

- Rust ≥ 1.94 (stable), Node 22, `protoc` (needed by LanceDB's build scripts).
- Windows: MSVC build tools; WebView2 (preinstalled on Windows 10/11).
- Linux (dev/CI): the usual Tauri system packages (`libwebkit2gtk-4.1-dev`, …) if you build the app.

## Building

```powershell
npm ci
npx tauri dev       # app in dev mode (builds rag-mcp as a sidecar first)
npx tauri build     # installers in target/release/bundle (NSIS .exe + .msi)

cargo build --release -p rag-mcp   # MCP server only
```

`tauri build` runs `npm run build && node scripts/prepare-sidecar.mjs`, which builds `rag-mcp` into the shared `target/` dir and, on Windows, fetches the Windows ML runtime. `src-tauri/build.rs` stages the sidecar and DLLs for bundling.

### ONNX Runtime flavours

`rag-core` needs exactly one ORT feature; `rag-mcp` and the app pick it per platform:

| Feature | Used on | What it does |
|---|---|---|
| `winml` | Windows (default) | Loads `onnxruntime.dll` (ORT 1.28) from the Windows ML NuGet package `Microsoft.Windows.AI.MachineLearning` 2.5.96 next to the exe (`ort` `load-dynamic`). DirectML built in; certified vendor execution providers (NVIDIA TensorRT-RTX, AMD, Intel OpenVINO, Qualcomm QNN) are listed, downloaded and registered through the Windows ML catalog (`rag_core::winml`, flat C API via `libloading`). |
| `cuda` | Linux | Bundled ORT (prebuilt download) + CUDA execution provider; falls back to CPU. Needs the CUDA 13 runtime + cuDNN 9 on the machine (`ort 2.0.0-rc.15` only ships CUDA 13 binaries; set `ORT_CUDA_VERSION=13` when building). |
| `bundled` | anywhere | Bundled ORT, CPU only. |

`scripts/fetch-winml.mjs` downloads and checksum-verifies the NuGet package (pinned version + sha256) into `src-tauri/binaries/winml/`. For tests on Windows point the runtime at it:

```powershell
node scripts/fetch-winml.mjs
$env:LOCAL_CODE_RAG_WINML_DIR = "$PWD\src-tauri\binaries\winml"
```

The vendor provider catalog needs Windows 11 24H2+; DirectML works on any Windows 11.

### Build speed

- **cargo-hakari:** `crates/workspace-hack` makes every crate build LanceDB and the rest of the dependency tree with the same features, so switching between `rag-mcp`, the app and the tests doesn't recompile them. ONNX Runtime crates and fastembed are excluded on purpose (`.config/hakari.toml`). After changing dependencies: `cargo hakari generate && cargo hakari manage-deps`. CI fails when it's stale.
- **Size of the tree:** about 620 crates for the app, mostly LanceDB (DataFusion + Lance; its cloud-storage features are off), FastEmbed/ORT and Tauri.
- **Locally on Windows:** put the repo on a Dev Drive or exclude `target/` from Defender real-time scanning; optionally use `sccache` (`RUSTC_WRAPPER=sccache`).
- `profile.dev` keeps heavy dependencies at `opt-level = 2` and uses line-tables-only debug info.

## Tests

```bash
cargo test -p rag-core --features bundled -p rag-mcp            # unit + fast integration tests
cargo test -p rag-core --features bundled --test e2e -- --ignored   # end-to-end with a real model (downloads bge-small)

# Windows ML
cargo test -p rag-core --features winml -p rag-mcp
cargo test -p rag-core --features winml --test winml_smoke -- --ignored --nocapture   # real embedding, lists the EP catalog
```

The ignored e2e tests cover indexing + incremental sync, FP16 vs FP32, INT8, export/import, and the quality features (scope context, licence-header skipping, identifier splitting, filters, merged results). Set `RAG_TEST_MODELS=<dir>` (Unix) to reuse a model cache between runs.

## CI and releases

- **`develop`** is the working branch. `ci.yml` runs on pushes to `develop` and `claude/**`, on PRs and manually: hakari check + tests on Linux (sccache) and Windows (Windows ML, `rust-cache` of `target/`), plus a Windows installer as a build artifact.
- **`main`** is release-only. `release.yml` runs on every push to `main`:
  1. reads `version` from `src-tauri/tauri.conf.json` and stops if release `v<version>` already exists,
  2. builds the signed installer (no tests: `main` only receives commits CI already tested on `develop`),
  3. publishes GitHub Release `v<version>`: `LocalCodeRAG_<ver>_x64-setup.exe` + `.sig`, `.msi`, `latest.json` (for the updater) and `rag-mcp-v<ver>-windows-x64.zip`, with generated notes.

**To release:** bump the version in `Cargo.toml` (`[workspace.package]`), `src-tauri/tauri.conf.json` and `package.json` on `develop`, wait for CI to pass, then merge (fast-forward) into `main`.

### Updater signing

The Tauri updater verifies every update against a public key built into release builds. Key material lives only in the GitHub environment **`release`**:

| Name | Kind | Value |
|---|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | secret | contents of the private key file |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | secret | its password |
| `TAURI_UPDATER_PUBKEY` | variable | contents of the `.pub` file |

Generate once with `npx tauri signer generate -w %USERPROFILE%\.tauri\local-code-rag.key` and keep the private key safe: every future release must be signed with it. The release job injects the public key with `tauri build --config release.conf.json` (`createUpdaterArtifacts: true`). Dev and CI builds have an empty `pubkey`, so updates are disabled there. Endpoint: `https://github.com/datorkar/Code-Rag-MCP/releases/latest/download/latest.json`.

## First-run setup

`SetupWizard.tsx` runs when `setup_completed` is false and no index exists (or from Settings). `rag_core::hardware` reads CPU threads, RAM (`GlobalMemoryStatusEx`) and display adapters with dedicated VRAM from `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-…}` (`DriverDesc`, `HardwareInformation.qwMemorySize`). Adapters with < 2 GB dedicated memory or well-known iGPU names count as integrated. `recommend()` maps this to a tier: discrete ≥ 6 GB / discrete < 6 GB → jina-code, Auto; integrated only → bge-small, Low; no GPU → bge-small INT8, Low. The wizard saves `active_embed_model`, `default_precision` (preselected for new indexes) and `resource_mode`.

## Data layout

`%APPDATA%\local-code-rag\` (Windows) · `~/.local/share/local-code-rag/` (Linux) · override with `LOCAL_CODE_RAG_HOME`.

```
config.json              global settings + per-index config
manifests/<id>.json      fingerprint, relative_path -> {blake3, size, mtime}, boilerplate header hashes
locks/<id>.lock          advisory lock (app indexing vs MCP search/auto-sync)
lancedb/idx_<id>.lance   path, start_line, end_line, text, context, fts_text, text_hash, vector
models/                  Hugging Face model cache
```

An index's **fingerprint** (`v3|model|chunk size|overlap[|int8][|dp]`) is stored in its manifest; when the config changes it, the next sync is a full rebuild.

Environment variables: `LOCAL_CODE_RAG_HOME` (data dir), `LOCAL_CODE_RAG_WINML_DIR` (Windows ML runtime dir), `LOCAL_CODE_RAG_FP16=0|1` (override FP16 on GPU), `RUST_LOG` (logging; `rag-mcp` logs to stderr only).

## How indexing works

1. **Walk** `root_path` with `ignore` (respects `.gitignore`, skips `ignore_dirs` by name at any depth, filters extensions, skips files over `max_file_bytes`).
2. **Hash** in parallel with blake3. Files whose size and mtime match the manifest aren't re-read, so a no-change sync is a directory walk. An empty scan of a previously indexed folder aborts instead of deleting everything (unless *Full rebuild*).
3. **Boilerplate detection** (full rebuilds only): each file's leading comment block is normalised (years → `#`, whitespace collapsed) and hashed; blocks that start ≥5% of files (min. 20) are stored in the manifest and skipped by the chunker (`rag_core::boilerplate`).
4. **Diff** against the manifest; delete chunks of removed/changed files (their vectors are kept by text hash for reuse).
5. **Chunk** in parallel: tree-sitter code splitting for C/C++/HLSL (`.usf/.ush`), Rust, C# and Python, a plain-text splitter otherwise; 1-based line ranges. Each chunk gets its **scope context** from the syntax tree (`namespace X > class UFoo > void UFoo::Tick(float)`). Chunk size is capped to what the model can read (≈2.75 chars/token minus header room).
6. **Embed:** unchanged chunks reuse their stored vector; duplicates are embedded once; the rest are sorted longest-first and batched by a token budget (GPU 32k / CPU 8k, shared by up to 2 GPU workers, also capped by batch × length²). Batches split automatically on out-of-memory. The model sees `// File: path`, `// In: context` and the code (plus the model's own document prefix, e.g. `search_document:`).
7. **Write** to LanceDB in a separate task while embedding continues; the manifest is saved as files complete, so a cancelled sync resumes.
8. **Index:** small syncs update the keyword index incrementally; ≥10% changed rows → compact, rebuild the BM25 index on `fts_text` (code + context + split identifiers, no stemming/stop words), a BTree on `path`, prune old versions. No ANN vector index: exact vector search is fast enough and IVF-PQ only matched ~76% of exact results on code embeddings.

**Precision:** *Standard* loads `onnx/model_fp16.onnx` on GPU (identical results) and FP32 on CPU; *INT8* loads `onnx/model_quantized.onnx` and is a separate fingerprint. Missing variants fall back to FP32.

**Resource modes:** *Low* = below-normal priority, logical threads − 2, one worker, CPU-sized batches; *Max* = normal priority, all threads, 2 GPU workers; *Auto* = Low on integrated-GPU/CPU machines, below-normal priority otherwise. After a sync the worker sessions are freed; the app unloads all models when no job runs, and `rag-mcp` unloads them after 15 minutes without searches.

## How search works

1. Embed the query (with the model's query prefix).
2. LanceDB hybrid search: vector + BM25 over `fts_text` (the query is also split into identifier parts), fused with Reciprocal Rank Fusion, optionally pre-filtered by `path_filter` (glob → SQL `LIKE`) and `extensions`.
3. Rerank the top `rerank_candidates` (30) with a cross-encoder (default `jinaai/jina-reranker-v2-base-multilingual`).
4. Merge overlapping/adjacent hits of the same file (text re-read from disk), keep `limit`.
5. Trim each hit to the `snippet_max_lines` lines that best match the query terms.

**Auto-sync on search** runs inline only when `auto_update_on_search` is on, the cooldown has passed, at most `auto_sync_max_files` files changed and no full rebuild is needed; otherwise the search answers from existing data with a note. If the app is indexing, search proceeds on the last committed data (LanceDB reads are MVCC-safe).

## MCP tools (`rag-mcp`)

| Tool | Arguments | Purpose |
|---|---|---|
| `list_indexes` | – | ids, names, roots, models, chunk counts, last update, status |
| `search_index` | `index_id`, `query`, `limit` (6), `path_filter`, `extensions` | hybrid search (auto-syncs small changes first) |
| `reindex_path` | `index_id`, `force_full` | manual sync |

Manual registration: `claude mcp add --transport stdio --scope user local-code-rag -- "<install dir>\rag-mcp.exe"`. The app's **Install to Claude Code** runs this (the `claude` CLI is resolved on `PATH` and started directly, without a shell).

## Export format (`.lcrag`)

One zstd stream (level 3): `MAGIC | u64 len + meta JSON | u64 len + manifest JSON | Arrow IPC stream`. Vectors are stored as FP16; mtimes are zeroed; the root path is stripped. Format 2 adds `context`/`fts_text` columns and the manifest's boilerplate list. On import, paths must be relative without `..`, every chunk's text and scope labels must occur in the importer's local file (else that file is dropped and re-embedded), and `fts_text` is recomputed locally.

## Security notes

- No shell is used to start processes; links open via `ShellExecuteW`, restricted to this repo's release pages.
- The current directory is removed from the DLL search path at startup; runtime DLLs load by absolute path.
- Network: Hugging Face (models), Microsoft (Windows ML providers), GitHub (updates). All use the OS certificate store and system proxy (`third_party/hf-hub` patches hf-hub's TLS roots).
- Tauri capabilities: `core:default`, `dialog:default`, `clipboard-manager:allow-write-text`; strict CSP.
